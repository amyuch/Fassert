# Obligation IR and schemas

The IR includes typed `btor-expression` bindings, `btor-smt` certificates,
projection `discharge` witnesses, compiled helper model/constraint annotations,
`proof.model_artifacts`, guarantee `binding`, `btor-projection` certificates, and
case target `required_properties`. Guarded roots are bound to properties of the
frozen primary model rather than only to English statement text. See
[`09-composition-guard.md`](09-composition-guard.md) and
[`10-solver-bridge.md`](10-solver-bridge.md).

This document is the human-readable companion to `schema/case.schema.json`,
`schema/obligation.schema.json`, and `schema/proof.schema.json`. Complete
acceptance requires `acceptance: "complete"` in both case and proof and
`metadata.completeness: "complete"`; K12 then rejects design TCBs, direct target
TCBs, assumption helpers/cuts, non-proved/`OPEN`/`UNKNOWN` nodes, and
`STRUCTURAL` roots.

The IR is deliberately small. It is a **proof-carrying record**, not a new
modeling language: model semantics live in the engine/BTOR/AIG, and the IR names
the facts, phases, guarantees, and evidence that the kernel composes. The case
target is frozen, and the kernel checks the root implication over the
planner-defined guarantee formulas.

---

## 1. Design goals

- typed enough that a kernel can match premises to guarantees and regenerate
  checkable evidence from their formulas;
- phase-aware (entry / loop / exit / any);
- explicit evidence and verdict, never a prose status;
- immutable model and artifact identities;
- canonicalisable for hashing;
- extensible by obligation kind/backend without changing the kernel's
  composition logic;
- no case-specific fields.

The IR does not encode full RTL semantics. A guarantee may be an engine-level
predicate (for example an assertion name on a model) or a logic formula (for
example an `Int` relation). The certificate says which, and the checker/replay
binding says how it was established.

---

## 2. Versioning

Every document has a `schema_version`:

- `pcd-case/0.1`
- `pcd-obligation/0.1`
- `pcd-proof/0.1`

Schemas are JSON Schema Draft 2020-12. A version change is required for any
breaking field change. Additive fields with defaults may stay in the same minor
version until the kernel needs to distinguish them.

---

## 3. Case

`schema/case.schema.json`

A case is data. It contains no proof and no helper contract.

```json
{
  "schema_version": "pcd-case/0.1",
  "case": "toy",
  "claim_scope": "safety",
  "inputs": {
    "files": [
      {"path": "input/rtl/toy.sv", "role": "rtl"},
      {"path": "input/spec/toy.spec", "role": "spec"}
    ],
    "environment": {"top": "toy", "reset": "reset", "frontend": "yosys-slang"}
  },
  "build": {
    "kind": "btor",
    "recipe": {"command": ["sh", "build/build.sh"]},
    "outputs": [{"path": "build/toy.btor", "kind": "btor"}]
  },
  "targets": [
    {
      "id": "root",
      "statement": "the architectural result equals the spec",
      "guard": "!reset && valid",
      "observation": "retire",
      "claim_level": "root",
      "model": "sha256:..."
    }
  ],
  "budgets": {"total_seconds": 900, "max_iterations": 4},
  "run_policy": {
    "mode": "blind",
    "oracle_paths": ["oracle/"],
    "pre_registered": true,
    "planner": "template"
  }
}
```

Rules:

- `inputs.files[].role` has no `contract`, `helper`, `proof`, or `oracle`
  value. Those are not inputs.
- `build.recipe` must be deterministic; `build.expected_model` records the
  expected identity when known.
- `targets` are frozen before planning. A target carries either a concrete
  `model` hash or `"model_ref": "primary"`; the latter is resolved by the build
  record and checked against the proof's primary model.
- `run_policy.oracle_paths` is what the blind harness must hide.

---

## 4. Model identity

A model is:

```
model_id = "<kind>:<sha256>"
```

Examples: `btor:<hex>`, `aig:<hex>`, `smt2:<hex>`.

The proof has:

```json
"models": {
  "primary": "btor:...",
  "isolated": "btor:..."
},
"primary_model": "btor:..."
```

Every non-TCB obligation names a model in `models` (or the primary model).
A non-primary model requires a `reuse` block and a `transfer` node.

The hash is identity, not semantic equivalence. Source-to-model equivalence is a
separate `rtl_link`/`transfer` obligation or an explicit TCB.

## 5. Obligation

`schema/obligation.schema.json`

```json
{
  "schema_version": "pcd-obligation/0.1",
  "id": "loop.invariant",
  "role": "invariant",
  "kind": "inductive",
  "phase": "loop",
  "model": "btor:...",
  "statement": "human-readable note; not the proof object",
  "requires": [{"node": "loop.manifold", "guarantee": "G1"}],
  "provides": [{"name": "G2", "expr": "dividend < 2 * divisor", "sort": "Bool"}],
  "certificate": {"...": "..."},
  "reuse": {"...": "..."},
  "coverage": {"...": "..."},
  "cut": {"...": "..."},
  "helper": {"kind": "monitor"},
  "simultaneous_group": "loop-invariants"
}
```

### 5.1 Roles

`invariant`, `update`, `algebra`, `terminal`, `temporal`, `select`, `operand`,
`observe`, `rtl_link`, `transfer`, `abstraction_gate`, `coverage`, `interface`,
`compose`, `tcb`.

### 5.2 Kinds

`inductive`, `poly`, `linear`, `guarded`, `ordering`, `macro_step`,
`over_approx`, `equivalence`, `replay`, `tcb`.

### 5.3 Phases

`entry`, `loop` (active), `exit` (finish/terminal), `any`.

A cycle is allowed only if all nodes in the cycle share a
`simultaneous_group` and the same phase.

### 5.4 Guarantees

A guarantee has a name (unique within the node), an expression, and a sort
(`Bool`, `Int`, `BV<width>`, `SMT`). The expression is the *exported* fact.

`requires` names `(node, guarantee)`. The kernel checks:

- the node exists;
- the guarantee exists in that node's `provides`;
- the premise is discharged (`CHECKED`/`REPLAY`, or TCB only where the target
  allows).

A compose certificate's `premises` must be exactly the target's `requires`.

### 5.5 Cut contracts

A cut is a contract over existing obligations, not a new assumption. It may be
attached to an `interface`, `observe`, `invariant`, `transfer`, or
`abstraction_gate` node:

```json
"cut": {
  "boundary": "picorv32_pcpi_div",
  "entry": [{"node": "enter", "guarantee": "G1"}],
  "step": [{"node": "loop", "guarantee": "G2"}],
  "exit": [{"node": "finish", "guarantee": "G3"}],
  "link": [{"node": "observe", "guarantee": "G4"}],
  "guards": [{"name": "busy", "expr": "busy"}, {"name": "idle", "expr": "!busy"}],
  "coverage": {"node": "guard.coverage", "guarantee": "G5"},
  "assumption_cut": false
}
```

`entry`/`step`/`exit`/`link` reference facts that are already in the node's
`requires`. `guards`, when present, must match a checked `coverage` node's guard
partition. An assumption cut is not complete evidence. K11 also requires the cut/helper
node to be consumed by another obligation or a target.

### 5.6 Helper roles

`helper.kind` is `monitor`, `assumption`, or `submodel`:

- `monitor`: same primary model, `REPLAY` or `CHECKED` evidence, never TCB.
- `assumption`: explicit `TCB` evidence; not accepted for a complete claim.
- `submodel`: a non-primary model plus a `reuse`/`transfer` obligation.

A helper is an obligation. Its role does not make it free, and a TCB helper
remains visible in `target.tcb`.

## 6. Certificate

The certificate is a tagged union over `evidence`.

### 6.1 `CHECKED`

```json
{
  "evidence": "CHECKED",
  "format": "poly",
  "checker": "pcd-poly/0.1",
  "verdict": "proved",
  "goal": "G2",
  "payload": {
    "W": 32,
    "subst": {"a": [[1, ["x"]], [1, []]]},
    "lhs": [[1, ["a", "a"]]],
    "rhs": [[1, ["x", "x"]], [2, ["x"]], [1, []]]
  },
  "artifact": {"path": "artifacts/...", "sha256": "..."}
}
```

`format` must have a checker. Supported formats are `poly`,
`smt-implication`, `smt-induction`, `miter`, `witness`, and `transfer`. Unsupported formats are rejected, not silently
trusted. The poly checker is bound to the obligation itself: it parses the
named guarantee's expression with the restricted typed language in
`checkers/expr.py` and checks its polynomial normal form over Z/2^W. An empty or
syntactically identical identity (a `0 = 0` certificate) is rejected. If an
optional `lhs`/`rhs` payload is present it is checked as an additional witness,
but it cannot replace the formula check.

The `smt-induction` checker accepts only a structured transition-system
payload (`vars`, `init`, `step`, `inv`, `exit`, and `goal`) and regenerates the
three implications

```text
premises & init        => inv
premises & inv & step  => inv[next]
premises & inv & exit  => goal
```

through the same restricted expression encoder. The planner cannot supply an
arbitrary SMT script or a precomputed UNSAT payload; helper guarantees arrive as
typed Boolean premises from the proof graph, and `_next` variables are the
explicit next-state image. A valid induction is therefore a CHECKED composition
over the transition relation, not an engine verdict promoted to a proof.

The certificate's `goal` must name one of the node's guarantees, binding the
certificate to the obligation. A `CHECKED` certificate cannot be justified by
prose, an unbound artifact, or an arbitrary SMT script.

### 6.2 `REPLAY`

```json
{
  "evidence": "REPLAY",
  "format": "replay",
  "verdict": "proved",
  "goal": "G1",
  "run": {
    "id": "run-0007",
    "command": ["ric3", "check", "dut.btor", "ic3", "--prop", "3"],
    "tool": "ric3",
    "version": "1.6.0",
    "model_sha256": "btor:...",
    "log": "logs/run-0007.log",
    "log_sha256": "..."
  },
  "assertion": {"name": "h_inv", "file": "helper.sv"}
}
```

`run.model_sha256` must equal the node's model. `log` is optional only if
`log_sha256` is present and the log is archived elsewhere; if `log` is present,
the kernel verifies its hash. `REPLAY` means "the engine verdict is bound and
reproducible", not "independently checked".

### 6.3 `TCB`

```json
{
  "evidence": "TCB",
  "format": "tcb",
  "verdict": "assumed",
  "tcb": "Yosys/Slang front-end; hash is identity, not equivalence"
}
```

A TCB node must be listed by the target that depends on it. A TCB premise is
allowed only when the consuming target declares that node in `target.tcb`;
otherwise K3 rejects it. A non-TCB premise must be `CHECKED` or a proved
`REPLAY`.

## 7. Reuse and transfer

```json
"reuse": {
  "source_model": "btor:...",
  "assumption_match": ["model", "width", "guards", "phase", "transition"],
  "transfer_node": "xfer.isolated_to_primary",
  "note": "..."
}
```

- `source_model` must equal the node's model.
- `assumption_match` must contain all five dimensions.
- `transfer_node` must exist, have role `transfer`, and be `CHECKED`.
- The transfer node's premises must include the source-model facts; its
  conclusion is the target-model fact.

A prose `note` may explain the transfer but is not evidence.

---

## 8. Coverage

```json
"coverage": {
  "guards": [
    {"name": "taken", "expr": "divisor <= dividend"},
    {"name": "not_taken", "expr": "!(divisor <= dividend)"}
  ],
  "exhaustive": true,
  "checked_by": "root.coverage"
}
```

K5 requires a non-empty guard list, `exhaustive: true`, and a checker or a
checked node. A boolean `coverage_checked` without the partition is not enough.

## 9. Proof

`schema/proof.schema.json`

```json
{
  "schema_version": "pcd-proof/0.1",
  "case": "toy",
  "models": {"primary": "btor:..."},
  "primary_model": "btor:...",
  "helpers": [{"path": "helper.sv", "asserts": [{"node": "inv", "name": "h_inv"}]}],
  "nodes": [],
  "targets": [
    {
      "id": "root",
      "statement": "...",
      "model": "btor:...",
      "goal": "P",
      "requires": [{"node": "inv", "guarantee": "G2"}],
      "tcb": ["O0"],
      "composition": {
        "mode": "CHECKED",
        "checker": "z3-implication",
        "payload": {
          "premises": [{"node": "inv", "guarantee": "G2"}],
          "goal": "P",
          "smt2": "(assert ...)(check-sat)"
        },
        "artifact": {"path": "artifacts/compose.smt2", "sha256": "..."}
      }
    }
  ],
  "metadata": {"run_mode": "blind", "planner": "template"}
}
```

- `nodes` are obligations.
- A target is a root obligation (`role: compose`) plus the composition record.
- `goal` names a guarantee provided by the root node (or an explicit target
  formula).
- A complete root requires `composition.mode = "CHECKED"`.
- `composition.mode = "CHECKED"` requires a checker and a payload whose
  `premises` exactly match `targets[].requires`.

The `z3-implication` checker does **not** trust the supplied script as an
independent object. It regenerates the exact canonical encoding of the target's
premise guarantee formulas and goal formula, compares the script to that
encoding, and then asks z3 whether it is unsat. The encoding is the small typed
language in `checkers/expr.py`; SMT premises and goals must be `Bool`.
Consequently `(assert false)` or any other conveniently unsat but unbound script
is rejected, and an unencodable or wrongly sorted formula cannot become a
`CHECKED` composition.

Planner proposals name an engine/backend from the frozen trusted catalog in
`pipeline/backends.py`. The runner resolves the command from that catalog; a
proposal command is allowed only when it exactly matches the resolved command.

## 10. Proposals and diagnostics

`schema/proposal.schema.json` is the planner-facing schema. A proposal contains
`nodes`, `targets`, and a `planner` identity, and deliberately has no
status/verdict/level fields. `pipeline/plan.py` validates it and freezes it
before discharge.

`schema/diagnostic.schema.json` is a separate diagnostic record, not part of a
proof. It has `evidence: "DIAGNOSTIC"`, `proof: false`, a status
(`cti`, `no_cti`, `cex`, `unknown`, or `error`), property entries, and zero or
more CTI entries. Each CTI copies `cti`, `cti.vcd`, `inv.ron`, `select.ron`,
`state.ron`, and `statistic.ron` into the run, binds their hashes, and records a
bounded VCD summary (named signals, frames, final values, changes). A CTI is
recorded only when the trusted `cill select` succeeds and the selected property
has satisfiable state frames. Timeouts, missing artifacts, and `UNKNOWN` are
`unknown`, never CTIs.

A later frozen iteration may bind a diagnostics file into `context.json` via
`--diagnostics-context`; the context includes the file hash and a bounded CTI
view. The file stays diagnostic-only and is not admitted to any proof.

K10 requires that proposals and verdicts are separate records. The discharge
record (`discharge.json`) holds engine verdicts; the proposal never does.

---

## 11. Canonicalisation and hashing

- JSON objects are canonicalised (sorted keys, no insignificant whitespace)
  before hashing.
- Paths are relative to the case/proof root.
- A `sha256` is 64 lowercase hex characters.
- A model id is `<kind>:<sha256>`; the hash covers the model file.
- A run id is immutable; re-running creates a new id.

---

## 12. Kernel interpretation

The kernel reads the proof, validates the schemas, then:

1. checks references and duplicates;
2. checks each certificate (`poly`, `smt-implication`, and `smt-induction`
   bound to the named guarantee formula, replay binding, TCB);
3. checks dependencies/guarantees/cycles;
4. checks transfer, coverage, reuse, model registry;
5. checks per-node artifacts and helper hygiene;
6. checks proposal/verdict separation;
7. checks cut contracts and helper roles (K11);
8. checks root composition and computes levels.

It never calls an engine. `pcd discharge` and `pcd replay` are the online
paths that produce `REPLAY` evidence; `pcd check` is offline.

## 13. Open IR questions

- How much of a guarantee should be a typed formula vs an opaque engine-level
  predicate?
- Do we need explicit quantifiers/phases beyond `entry/loop/exit/any`?
- How do we bind an engine assertion name to an IR guarantee without trusting a
  free-text name mapping?
- Should transfer certificates be miter-based, relation-based, or both?
- When can an engine witness (IC3 clauses, AIGER proof) be checked
  independently?
