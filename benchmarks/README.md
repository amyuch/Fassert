# Benchmarks

Self-contained benchmark cases for the fassert/CIll toolchain. Each runnable case
directory contains the RTL, harness, properties/checkers, and `ric3.toml` needed
to build it. Generated `ric3proj/` directories are not part of the package, and
no case reads from an external source tree or generated project.

## Active families

| Family | Cases | Layout | Entry |
|---|---:|---|---|
| `picorv32/` | 43 active | 40 non-ALT OPS cases + 3 ALTOPS variants; full list in `picorv32/manifest.csv` | `cd <case> && ./run.sh` |
| `picorv32_full/` | 30 preserved | unselected cases from the original 70-case corpus | `cd <case> && ./run.sh` |
| `picorv32_fullcheck/` | 73 | full-property checker over the active + preserved picorv32 cases | `cd <case> && ./run.sh` |
| `serv/` | 4 | one directory per property (`causal`, `pc_bwd`, `pc_fwd`, `reg`) | `cd <case> && ./run.sh` |
| `nerv/` | 25 | one directory per instruction / CSR / bus property | `cd <case> && ./run.sh` |
| `flute/` | 17 | one directory per instruction | `cd <case> && ./run.sh` |
| `piccolo/` | 15 | one directory per instruction | `cd <case> && ./run.sh` |
| `riscv-formal/` | — | shared canonical library: 70 instruction specs + RVFI checkers | source for the RTL cases |

`test4neuroabs/` is a legacy corpus and is intentionally outside the active
benchmark set.

`picorv32_fullcheck/` mirrors all 73 rows in `picorv32/manifest.csv` but
replaces the reduced CIll checker with
`riscv-formal/rvfi_insn_check_origin.sv` (20 asserts instead of 2 for
instruction cases or 1 for load/store cases). The `picorv32` and
`picorv32_full` families remain the reduced benchmark set; use
`picorv32_fullcheck` when the property set must match the fuller RVFI
contract.

`test4neuroabs/fullcheck/` is a 99-case full-property variant of the legacy
NeuroAbs corpus (70 picorv32, 25 nerv, 4 serv), generated by
`test4neuroabs/make_fullcheck_cases.py`. See
`test4neuroabs/fullcheck/README.md` for the checker overrides and counts.

## Test lists

The active corpus is 104 cases.  `CATEGORIES.md` is the family/category
inventory, and `testlist.csv` records the 101 non-ALT OPS cases with cumulative
`smoke` (10), `core` (40), and `extended` (101) tiers.  The core suite is
23 picorv32, 4 serv, 3 nerv, 5 flute, and 5 piccolo cases.

`testlist_full.csv` is a separate 5-case official/full-property list using the
clean imports under `automation/pcd`: `insn_addi`, `insn_beq`, `insn_c_j`,
`insn_jal`, and `insn_mulh`.  All five also appear in the 23-case picorv32 set.
The three `_altops` variants are excluded because they only exercise the
abstracted add/sub path.  `benchmarks/picorv32_full/` is the preserved reduced
corpus, not the full-property list.

```sh
python3 run_testlist.py --tier smoke
python3 run_testlist.py --tier core --jobs 4
python3 run_testlist.py --tier extended
python3 run_testlist.py --tier full
python3 run_testlist.py --tier all        # 106 cases

python3 make_testlist.py --check          # validate/regenerate the CSV lists
```

`run_testlist.py` calls each reduced case's `./run.sh` (`ric3 build` plus a model
hash) and each official case's `build/build.sh`; proof overlays live in
`automation/decomp/`.  It checks build readiness only.  For an actual CIll run,
build one case and run `ric3 cill check` in that directory; no testbench is
required for `flute`/`piccolo` (see their family READMEs for the curated
commands).  `test4neuroabs/`, `test4neuroabs/fullcheck/`, and the preserved
`picorv32_full/` cases are not in the default lists.

## CIll input format

Every runnable case is a CIll input: a directory plus `ric3.toml`.

- `picorv32`, `serv`, and `nerv` list the design RTL, property/checker, harness,
  testbench, and include files explicitly in `ric3.toml`.
- `flute` and `piccolo` use `wrapper.v` as the design input. That file
  contains the design modules and the ILA property modules; `ric3.toml` points
  at it with `top = "wrapper"`. No separate input format is required.

A separate `tb.sv` is **not** required by rIC3/CIll.  It is simply the chosen
formal top for `picorv32`, `serv`, and `nerv` (`top = "testbench"`).  In
`flute` and `piccolo`, `wrapper.v` already contains the harness and clocked
properties, so `top = "wrapper"`; adding an unused `tb.sv` would not change the
CIll input.  See `flute/README.md` and `piccolo/README.md` for runnable CIll
commands.

Run a case:

```sh
cd <family>/<case>
./run.sh
# = ric3 build; then print the BTOR sha256
```

The `run.sh` scripts build the model and print its hash. They do not by
themselves claim `PROVED_CHECKED`; proof overlays and certificate checks live in
`automation/decomp/`.

## picorv32 selection

The active set is 43 cases. `picorv32/manifest.csv` lists all 73 case directories (70 originals + 3 ALTOPS variants) with:

- `case` — case name;
- `active` — `yes` for the active set, `no` for the preserved set;
- `group` — `alu`, `upper`, `mul`, `divrem`, `branch`, `jump`, `load`, `store`,
  or `compressed`;
- `semantics` — `normal`, `nonaltops`, or `altops`;
- `location` — the directory containing the case;
- `note` — why a case is interesting when it is a family/proof representative.

The selection keeps add/addi, mul/mulh, div, rem/remu, branch, jal/jalr, word
memory, compressed, upper, and xor/sra representatives.  `insn_xor` and
`insn_sra` were promoted from the preserved corpus to active cases.  All eight
MUL/DIV/REM base cases are real non-ALTOPS cases; three additional ALTOPS
representatives cover `mul`, `div`, and `rem`. The 30 unselected originals are
preserved under `picorv32_full/`, so the full corpus is still available without
cluttering the active set.

## Canonical inputs vs materialized cases

The shared sources are kept at:

- `benchmarks/riscv-formal/` — instruction specs and RVFI checkers;
- `benchmarks/picorv32/picorv32.sv` and `wrapper.sv`;
- `benchmarks/serv/rtl/` and `serv/wrapper.sv`;
- `benchmarks/nerv/nerv.sv` and `wrapper.sv`.

The `picorv32`, `serv`, and `nerv` case directories are materialized: shared
files are copied into each case so a case can be run in isolation. When a
canonical copy changes, refresh the affected cases by re-copying the
corresponding files.
